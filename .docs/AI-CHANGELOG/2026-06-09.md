## Fix: Rider Online Toggle & Order Notification Badge

### Root Cause Analysis

#### 1. Rider ไม่สามารถกด Online ได้ (SignalR WebSocket ล้มเหลว)
- **ปัญหา**: Nginx ใช้ `proxy_pass http://host.docker.internal:5000/hubs/` แบบ hardcode
- `host.docker.internal` resolves เป็น IPv6 address (`fdc4:f303:9324::254`) ก่อน IPv4
- .NET Backend ฟังเฉพาะ IPv4 (`127.0.0.1:5000`) ไม่ได้ฟัง IPv6
- สำหรับ HTTP request ธรรมดา Nginx retry upstream อื่นได้ → ผ่าน (นั่นทำไม negotiate 200 OK)
- แต่สำหรับ **WebSocket upgrade** Nginx ไม่ retry → connection ล้มเหลวทันที → SignalR ต่อไม่ได้ → goOnline() throw error

#### 2. Rider badge บน nav bar ไม่แสดง
- `MainShell` เป็น `StatelessWidget` ไม่ได้ watch provider ใดเลย
- ไม่มีการแสดง badge เมื่อมี dispatch offer เข้ามา

### Changes

#### `rider_app/nginx/default.conf` [MODIFIED]
```nginx
# เพิ่ม:
resolver 127.0.0.11 ipv4=on valid=30s;  # บังคับ IPv4-only DNS resolution
set $backend "http://host.docker.internal:5000";  # ใช้ variable ให้ nginx re-resolve ทุก request

# เปลี่ยน proxy_pass จาก hardcode URL → ใช้ $backend variable
# เพิ่ม headers ครบสำหรับ WebSocket: X-Real-IP, X-Forwarded-For
# เพิ่ม proxy_connect_timeout 10s, proxy_send_timeout 86400s
```

#### `rider_app/lib/app/app_router.dart` [MODIFIED]
- แปลง `MainShell` จาก `StatelessWidget` → `ConsumerWidget`
- เพิ่ม import `home_provider.dart`
- Watch `homeNotifierProvider` เพื่อรับ `incomingOffer`
- แสดง `Badge(backgroundColor: Colors.red, label: '!')` บนไอคอน "งานส่ง" เมื่อมี offer เข้ามา

### Deployment
- rebuild Docker image: `docker compose build rider-app`
- restart container: `docker compose up -d rider-app`
- verify nginx config: `docker exec delivery-rider-app nginx -t` → OK

## Fix: Backend Container Crash & Vault Bootstrap CRLF Issue

### Root Cause Analysis

1. **vault-bootstrap.sh CRLF Issue**
   - **ปัญหา**: ไฟล์ `scripts/vault-bootstrap.sh` ถูกเซฟด้วย Line Ending แบบ Windows (CRLF)
   - เมื่อ container `delivery-vault-bootstrap` นำไปรันด้วย `/bin/sh` จะเกิด syntax error: `unexpected end of file (expecting "do")` และทำให้ไม่สามารถสร้าง AppRole credentials (ไฟล์ `backend_role_id`, `backend_secret_id`) ใน directory `/vault/approle` ได้
   - ส่งผลให้ `delivery-backend` สตาร์ทไม่ผ่านด้วย error: `System.IO.FileNotFoundException: AppRole credential files not found.`

2. **Backend Workers TaskCanceledException Crash**
   - **ปัญหา**: ใน `HeartbeatMonitor.cs` และ `DispatchTimeoutWorker.cs` มีการใช้ `Task.Delay(..., stoppingToken)` นอกบล็อก `try-catch`
   - เมื่อระบบสั่ง Shutdown หรือ DB ยังไม่พร้อมใช้งาน และ `stoppingToken` โดนยกเลิก (Cancelled) จะทำให้ `Task.Delay` โยน `TaskCanceledException` หลุดออกนอก worker loop
   - ใน .NET 8 เมื่อเกิด Exception หลุดออกจาก BackgroundService พฤติกรรมเริ่มต้น (`BackgroundServiceExceptionBehavior`) คือ `StopHost` (สั่งปิดทั้ง Application) ส่งผลให้ Backend คอนเทนเนอร์แครชทันทีและกลายเป็น Unhealthy

### Changes

#### `scripts/vault-bootstrap.sh` [MODIFIED]
- แปลง Line Endings จาก Windows CRLF (`\r\n`) เป็น Linux LF (`\n`) เพื่อให้ execute ในคอนเทนเนอร์สำเร็จ

#### `BackendApi/Services/BackgroundWorkers/HeartbeatMonitor.cs` [MODIFIED]
- ย้าย `Task.Delay` เข้าไปอยู่ภายใต้บล็อก `try-catch` และเพิ่มการดักจับ `OperationCanceledException` เพื่อให้ Shutdown ได้อย่างราบรื่นโดยไม่แครชโฮสต์

#### `BackendApi/Services/BackgroundWorkers/DispatchTimeoutWorker.cs` [MODIFIED]
- ย้าย `Task.Delay` เข้าไปอยู่ภายใต้บล็อก `try-catch` และดักจับ `OperationCanceledException` เพื่อแก้ไขสาเหตุการแครชแบบเดียวกัน

### Verification
- รัน `docker compose restart vault-bootstrap` เพื่อทำการ config Vault และสร้าง Credentials
- รัน `docker compose restart backend` เพื่อตรวจสอบการเริ่มทำงานของ backend API
- ผลลัพธ์: ทุกคอนเทนเนอร์รันได้เป็นปกติ สถานะของ `delivery-backend` คือ `Up (healthy)`

## Fix: Nginx Proxy Pass HTTP 404 (Path Duplication with Variables)

### Root Cause Analysis
- **ปัญหา**: เมื่อเข้าหน้าเว็บแอป Rider App แล้วพยายาม Login จะได้ error HTTP 404 Not Found กลับมาจาก API (`/api/v1/auth/login`)
- ใน Nginx configuration (`default.conf`) ก่อนหน้านี้ได้ทำการเปลี่ยน `proxy_pass` ให้ใช้ dynamic variable `$backend` เพื่อบังคับ DNS resolver ให้ค้นหาเฉพาะ IPv4:
  `proxy_pass $backend/api/;` และ `proxy_pass $backend/hubs/;`
- **การทำงานจริงของ Nginx**: เมื่อใช้ dynamic variables ใน `proxy_pass` ร่วมกับ path suffix (เช่น `/api/` หรือ `/hubs/`), Nginx จะไม่ทำ path translation แบบธรรมดา (ไม่ตัด `/api/` หรือ `/hubs/` ออกก่อนประกอบใหม่) แต่จะนำ **Request URI เต็ม** ไปต่อท้ายโดยตรง
- ผลลัพธ์คือ เมื่อร้องขอไปที่ `/api/v1/auth/login` Nginx จะส่งต่อไปยัง:
  `$backend/api//api/v1/auth/login` (หรือมีดับเบิ้ล `/api/api/v1/auth/login`) ส่งผลให้ Backend API ค้นหา Route ไม่เจอและตอบกลับเป็น **404 Not Found**

### Changes

#### `rider_app/nginx/default.conf` [MODIFIED]
- ปรับเปลี่ยน `proxy_pass` ภายใต้ location `/api/` และ `/hubs/` ให้ส่งตรงไปยัง `$backend` (โดยไม่มี path suffix) เพื่อให้ Nginx ส่ง Request URI ตัวจริงผ่านไปโดยตรงไม่มีการทำซ้ำ:
  - `proxy_pass $backend/api/;` ➡️ `proxy_pass $backend;`
  - `proxy_pass $backend/hubs/;` ➡️ `proxy_pass $backend;`

### Verification
- ทำการรีโหลดการตั้งค่า Nginx ภายใน container: `docker exec delivery-rider-app nginx -s reload`
- ทดสอบเรียก API ผ่าน Nginx (Port 8080): `curl.exe -i -X POST http://localhost:8080/api/v1/auth/login`
- ผลลัพธ์: ได้รับการส่งต่อและตอบกลับเป็น `HTTP 400 Bad Request` พร้อม JSON Validation Error จาก Backend API สำเร็จ (ยืนยันได้ว่าเชื่อมต่อสำเร็จ ไม่พบปัญหา 404 แล้ว)
