## 📱 2. Mobile App & Backend Integration (BUG-07 ถึง BUG-11)
* **BUG-07 & BUG-08 (Location Update & Accuracy Semantics):** พัฒนาฟังก์ชัน `sendLocationUpdate` ใน Flutter ให้รองรับการทำงาน และปรับเปลี่ยนการส่งค่า semantic จากส่ง speed เป็นส่ง `accuracy` ตามข้อกำหนด API ของระบบ telemetry หลักหลังบ้าน
* **BUG-09 (DTO Inconsistency):** ซิงค์ฟิลด์ `items`, `shopId`, และตัวแปรกลุ่มงานพ่วง (batch group details) ในโครงสร้างโมเดล DTO ทั้งของ Angular และ Flutter ให้แสดงผลตรงกัน
* **BUG-10 (Dangerous Feature Removed):** ลบฟีเจอร์และปุ่ม `deleteAllData()` / เอนด์พอยต์ `DELETE /orders/all` ทั้งระบบเพื่อความปลอดภัยระดับฐานข้อมูล (Security-by-Design)
* **BUG-11 (Generic Search in Base Controller):** พัฒนาลอจิก ApplySearch ใน `CrudControllerBase` โดยใช้ Dynamic Expression Trees และ Reflection ในการดึงและคัดกรองข้อมูลฟิลด์ที่เป็น string อัตโนมัติ

## 🛰️ 3. Multi-Drop & Stale State Sync Gaps (BUG-12 ถึง BUG-19)
* **BUG-12 (Multi-Drop Coords Broadcast):** พัฒนาคลาส `ActiveOrderRecipientCache` จัดเก็บรูปแบบ Hash ใน Redis และใช้สคริปต์ Lua อัปเดตแบบ Atomic เพื่อให้ลูปกระจายพิกัด GPS ของไรเดอร์ให้ทุกลูกค้าที่อยู่ในรอบงานพ่วงเดียวกัน (ไม่ถูกจำกัดไว้แค่ลูกค้ารายสุดท้าย)
* **BUG-13 (Cache Stale & Fallback):** ลดเวลาหมดอายุแคชแอคทีฟ (TTL) เหลือ 30 วินาที พร้อมเพิ่ม PostgreSQL query fallback เมื่อแคชตกหล่น ป้องกันพิกัดไรเดอร์รั่วไหลไปหาลูกค้าคนเดิมหลังจบงาน
* **BUG-14 & BUG-15 (Client Reset & Coordinates Null-Safety):** เพิ่มการรีเซ็ตพิกัดและล้าง Marker บนแผนที่ทันทีเมื่อ watch order หรือสลับออเดอร์ใหม่ พร้อมเพิ่ม null safety เช็คพิกัดของร้านค้า/ลูกค้า ป้องกันแผนที่บนโมบายแครช
* **BUG-16 (Telemetry Double-Counting):** ปรับเงื่อนไขคัดกรองใน `TelemetryBroadcastWorker` ไม่ให้นับไรเดอร์สถานะ `STALE` เข้าไปซ้ำซ้อนในจำนวน Active Riders
* **BUG-17 & BUG-18 (Missing SignalR Broadcasts):** เพิ่มการยิง SignalR อัปเดตสถานะออเดอร์กลับเป็น `MATCHING` เมื่อข้อเสนอถูกปฏิเสธหรือหมดเวลา (ใน `DispatchOfferHandler`) และบรอดแคสต์สถานะ `STALE`/`OFFLINE` หาแอดมินเมื่อไรเดอร์ขาดการส่งสัญญาณชีพ (ใน `HeartbeatMonitor`)
* **BUG-19 (Batch Cancellation UI/UX):** แสดง Dropdown ให้แอดมินเลือกยกเลิกออเดอร์แบบเจาะจงหรือยกเลิกทั้งหมดในรอบพ่วงได้ผ่านแผนที่ และใช้ `forkJoin` ส่งคำขอยกเลิกแบบขนานข้ามเครือข่าย

## 🚀 7. State Consistency & Rider Enum Alignment (แก้ไขเพิ่มเติม)
* **Rider Status Standardization:** ซิงค์รหัสสถานะไรเดอร์ให้ใช้แบบเดียวกันทั้งระบบ ได้แก่ `OFFLINE, IDLE, RESERVED, BUSY, STALE` และลบค่าสถานะเก่า/จำลอง เช่น `AVAILABLE` / `UNAVAILABLE` ออกจากโครงสร้างข้อมูล ตัวแปร DTO ฝั่งเว็บ (Angular) และฝั่งแอปมือถือ (Flutter) เพื่อป้องกันข้อมูลไม่ตรงกัน
* **Order Transition REST Refactoring:** ปรับปรุงหน้าติดตามเส้นทางของไรเดอร์ (`route_tracking_screen.dart`) จากเดิมที่ยิงสัญญาณสั่งแก้สถานะการจัดส่งออเดอร์ (`PICKING_UP`, `DELIVERING`, `COMPLETED`) ผ่าน SignalR Status Hub ไปเป็นการยิงอัปเดตสถานะออเดอร์ผ่านช่องทาง REST API หลักที่ถูกต้องและรองรับ state machine checks ในฐานข้อมูลจริง
* **Store Rejection Endpoint:** เพิ่มเอนด์พอยต์และสิทธิปฏิเสธออเดอร์ใหม่โดยเจ้าของร้าน (`POST /api/v1/orders/{id}/reject-by-store`) พร้อมปรับโครงสร้าง UI ของร้านค้าพันธมิตรให้ปุ่ม "ปฏิเสธ" ยิงเข้าเอนด์พอยต์ใหม่นี้ ป้องกันการทำงานข้ามบทบาท และแก้ไข UI ให้แสดงผลอัปเดตตาม response จริงจาก Server
