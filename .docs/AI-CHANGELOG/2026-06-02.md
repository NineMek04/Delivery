## 3. ป้องกันการขอ Token ซ้ำซ้อนระดับเครือข่าย (Concurrent Token Refresh Guard)
แก้ปัญหาคำขอ HTTP ยิงเบียดแย่งชิงสิทธิ์เปลี่ยนโทเค็นจนสุ่มสไลด์ผู้ใช้กลับหน้าล็อกอิน (Force Logout):
*   **Request Queueing**: ปรับเปลี่ยน `ErrorInterceptor` ใน [api_interceptors.dart](file:///d:/Delivery/rider_app/lib/core/api/api_interceptors.dart) ให้จดจำคิวและแช่แข็งคำขอ API ลำดับถัดไปที่พบ Error 401 เอาไว้ชั่วคราวผ่าน List queue ในกรณีที่ระบบกำลังทำทรานแซกชัน `/api/v1/auth/refresh`
*   **Concurrent Flusher**: เมื่อรีเฟรช Token สำเร็จ คำขอทั้งหมดที่ถูกแช่แข็งอยู่ในคิวจะถูกปล่อยออกไปอีกครั้งพร้อมๆ กันโดยอัตโนมัติพร้อมแนบ Token Bearer ชุดใหม่ หากรีเฟรชล้มเหลว คิวงานทั้งหมดจะถูกปฏิเสธ (Reject) และนำผู้ใช้กลับหน้า Login อย่างปลอดภัย
