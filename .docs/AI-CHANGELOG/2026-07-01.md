# [Dev Team] Changelog: 2026-07-01

## Optimization Naming Cleanup

- Reworded user-facing code comments, Swagger description, logs, and docs to
  avoid overclaiming "AI" where the implementation is deterministic ranking or
  mathematical optimization.
- Clarified that `scoring.py` is weighted heuristic / rule-based rider ranking,
  not a trained machine-learning model.
- Clarified that `vrp_solver.py` uses Google OR-Tools mathematical optimization
  over the current Haversine distance matrix.
- Renamed the Python component folder/service/container from `ai-engine` /
  `ai-service` to `route-optimizer` / `delivery-route-optimizer`.
- Implemented local OSRM `/table` as the primary VRP distance matrix source
  and preserved Haversine as deterministic fallback when OSRM is unavailable,
  incomplete, or invalid.
- Kept protected endpoint names and backend `IAiService` signatures as a
  compatibility facade while adding `ROUTE_OPTIMIZER_URL` and
  `ROUTE_OPTIMIZER_API_KEY` as the preferred configuration names.
- Updated Docker Compose override, scripts, test dashboard labels, and
  Prometheus metric naming to use route optimizer terminology.
