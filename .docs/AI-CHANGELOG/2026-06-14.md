## 1. Backend, Dispatch, Telemetry และ Migration Consolidation

**Commit:** `ea3c31323ee894d82d2f92e9c6b62cfd711a2e28`  
**Subject:** `feat: implement core backend telemetry, dispatch management, and rider heartbeat monitoring services`

### Dispatch และ State Correctness

* แก้การตีความผลลัพธ์ OSRM Trip ใน `BatchEvaluator` ให้เปรียบเทียบ visit order ด้วย `waypointVisitOrder[2]` และ `waypointVisitOrder[3]` โดยตรง แทนการใช้ `IndexOf()` ซึ่งทำให้ลำดับส่งออเดอร์พ่วงผิด
* แยก helper `ApplyDropoffVisitOrder()` และเพิ่ม regression tests สำหรับลำดับจุดส่งและ fallback เมื่อข้อมูล sequence ไม่สมบูรณ์
* ปรับ `HeartbeatMonitor` ให้ดึงออเดอร์สถานะ `OFFERING` ของไรเดอร์ที่ heartbeat หมดอายุเป็นชุดเดียว ลด N+1 database queries ภายในลูป

### Shop Partial Update Safety

* เปลี่ยน `ShopDto.IsOpen` เป็น `bool?` และ `PrepTimeMinutes` เป็น `int?`
* ป้องกันการเปิดร้านอัตโนมัติหรือรีเซ็ตเวลาเตรียมอาหารเป็น 15 นาที เมื่อ client แก้ไขเฉพาะข้อมูลร้านค้าบาง field
* เพิ่ม validation และ unit tests สำหรับ nullable partial-update fields

### GPS History และ Admin Map

* เพิ่ม `GpsHistoryService.GetHistoryAsync()` สำหรับอ่านพิกัดย้อนหลังตาม rider, ช่วงเวลา และจำนวนสูงสุด
* ปรับ `RiderLocationController` ให้คืน GPS history จาก PostgreSQL ผ่าน service layer
* ปรับ Admin Map ให้เรียกประวัติ 24 ชั่วโมงล่าสุด รองรับ `ApiResponse.value`, กรองพิกัด invalid และแสดงจำนวนจุด GPS ที่โหลดได้
* เพิ่ม error/empty-state feedback เมื่อโหลดประวัติ GPS ไม่สำเร็จหรือไม่มีพิกัดที่ใช้วาดเส้นทางได้

### Telemetry และ Observability

* เพิ่ม Prometheus metrics สำหรับ active orders, active riders, GPS throughput, AI latency, OSRM latency, rate-limit rejection และ token-refresh failure
* เพิ่ม timing metrics ให้ AI และ OSRM operations
* เปิด RabbitMQ Prometheus plugin และเพิ่ม scrape target port `15692`
* เพิ่ม Grafana dashboard `Delivery Operations` แบ่งเป็น Business Health, AI Performance และ System Health
* เปิด `preferCanvas: true` ใน Angular operational maps เพื่อลด Leaflet DOM overhead
* อัปเดต RabbitMQ publish batch ให้ใช้ `ReadOnlyMemory<byte>` ผ่าน `body.AsMemory()` แทน obsolete byte-array overload

### EF Migration Consolidation

* ยุบ EF migration chain เดิมเป็น baseline เดียว:
  `20260614152246_ConsolidatedBaseline20260614`
* คงโครงสร้าง migration เป็น baseline, Designer และ Model Snapshot เพื่อลดจำนวนไฟล์และขนาดการ build
* เพิ่ม `MigrationBaselineCompatibility` สำหรับ stamp baseline ใหม่ให้ฐานข้อมูลที่มี legacy migration chain ครบแล้ว
* ปฏิเสธฐานข้อมูลที่มี legacy migration เพียงบางส่วน เพื่อป้องกัน schema ถูกตีความผิดระหว่าง deployment
* แยก PostgreSQL-specific schema operations ไปไว้ใน `BackendApi/ServiceMigration/`
* เพิ่ม service migration แบบ idempotent สำหรับ index
  `IX_ProcessedEvents_ProcessedAt` โดยใช้ `CREATE INDEX CONCURRENTLY IF NOT EXISTS`
* อัปเดต startup migration flow ให้ทำ compatibility check ก่อน `Database.MigrateAsync()`

### Verification

* .NET build สำเร็จโดยไม่มี compiler warning
* C# automated tests ผ่านทั้งหมด 111 รายการ
* ทดสอบสร้าง fresh PostgreSQL database จาก consolidated baseline สำเร็จ
* ทดสอบ compatibility bridge กับฐานข้อมูลที่มี legacy migration history สำเร็จ
* ตรวจ Model Snapshot และ operational indexes ให้ตรงกับ schema ปัจจุบัน

## 2. Active Architecture และ Contract Documentation

**Commit:** `1a856f3634ad89b3b2f2f43090fbddff7c5be47c`

  `AGENTS.md`/critical rules -> active contracts -> implementation/tests -> historical archives
* กำหนดให้รักษากฎด้าน security, correctness, data integrity และ resilience เมื่อ implementation ปัจจุบันยังต่ำกว่ามาตรฐาน

### Component Specifications

* ปรับ active specs ของ Backend, Angular, Flutter, AI Engine และ Infrastructure ให้ตรงกับโครงสร้าง repository ปัจจุบัน
* แก้ stack และ topology ให้ตรงกับ PostgreSQL 15, PgBouncer, Local OSRM MLD, RabbitMQ, Vault และ observability services
