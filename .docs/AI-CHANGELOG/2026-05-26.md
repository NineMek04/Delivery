### Component: BackendApi — High-Frequency Telemetry & Spatial Performance
- **Action:** พัฒนา `TelemetryService.cs` เพื่อแยกส่วนการจัดการพิกัดเรียลไทม์ออกจาก Business Logic หลัก
  - **Redis-First Strategy:** จัดเก็บพิกัดล่าสุดลงใน Redis Cache เท่านั้นเพื่อรองรับ Throughput สูง
  - **Throttled Persistence:** ลดภาระฐานข้อมูล PostgreSQL โดยการเขียนข้อมูลตาราง `Riders` แบบ Throttled ทุก 10 วินาที
- **Action:** อัปเดต `TrackingHub.Location.cs` ให้ทำงานแบบ Non-blocking โดยเรียกใช้ `TelemetryService` ผ่าน `[FromServices]` และนำโค้ดที่บล็อกการทำงาน (Sync DB writes) ออกจาก Hot Path
- **Action:** ปรับปรุง `OsrmRoutingService.cs` เพิ่มฟังก์ชัน **Snap-to-Road** เพื่อเกาะพิกัดไรเดอร์ให้อยู่บนแนวถนนจริงเสมอ และติดตั้ง **Polly Circuit Breaker** ป้องกันระบบนำทางล้มเหลว
- **Action:** เสริมระบบความน่าเชื่อถือใน `DispatchService.cs`:
  - **Redis Distributed Lock:** ป้องกัน Race Condition ในการกดรับงาน (`AcceptOffer`)
  - **Concurrency Token Check:** ป้องกันข้อมูลขัดแย้ง (Optimistic Concurrency)
  - **Haversine Fallback:** ระบบคำนวณระยะทางสำรองกรณี AI Engine หรือ OSRM ขัดข้อง
- **Action:** ปรับปรุง `TelemetryBroadcastWorker.cs` ให้ประมวลผล **Demand Heatmap** (Grid ขนาด ~110 เมตร) โดยวิเคราะห์ออเดอร์ย้อนหลัง 1 ชั่วโมง และจัดเก็บผลลัพธ์ใน Redis เพื่อแสดงจุดความร้อนของออเดอร์บน Dashboard
