## 2. ฝั่ง Flutter Client (Rider Mobile App)
มีการนำระบบ Isar NoSQL Database และ Timer Synchronization Engine เข้าไปครอบเป็นโล่ป้องกันข้อมูลหล่นหายระดับเครื่องโทรศัพท์ไรเดอร์:

*   **Isar Collection Definition (`gps_point.dart`)**:
    *   สร้าง Collection Model `GpsPoint` สำหรับ Isar database เพื่อเก็บพิกัด offline buffering ในรูปแบบ NoSQL database ประสิทธิภาพสูง มีความเร็วการเขียนอ่านที่รวดเร็ว
*   **Offline GPS Buffer & Sync Service (`gps_buffer_service.dart`)**:
    *   สร้าง Service และ Riverpod Provider คุมการซิงค์ข้อมูลลง Isar NoSQL
    *   **bufferLocation**: เก็บพิกัด GPS ลง Isar DB ทันทีแบบ Asynchronous Transaction และหากพบพิกัดสะสมตุนเกิน 10 จุดจะสั่ง Force Sync ทันทีเพื่อความต่อเนื่อง
    *   **syncBufferedPoints**: ดึงข้อมูล 100 จุดเก่าสุด ส่งหา Backend API ด้วย Dio Client และลบ (Purge) ออกจาก Isar ทันทีเมื่อได้รับสถานะ HTTP `200 OK`
    *   **Dynamic Backpressure**: อ่าน Header `X-Recommended-Ping` ของเซิร์ฟเวอร์เพื่อปรับแต่ง Sync interval อัจฉริยะ (เช่น ขยับจาก 3 วินาทีเป็น 15 วินาทีหากเซิร์ฟเวอร์แจ้งเตือนตึงมือมาก)
*   **Integration with Location Tracker (`location_service.dart`)**:
    *   เชื่อมโยงกับ `GpsBufferService` เพื่อเปิด sync timer อัตโนมัติเมื่อเริ่มติดตาม GPS และปิดทันทีเมื่อหยุด GPS tracking
    *   ปรับการทำงานใน `_onPositionUpdate` ให้ส่งพิกัดไปเก็บที่ Isar DB Offline Buffer แทนการยิงตรงผ่าน SignalR (ยกเว้นระบบ Web Mock Fallback) เพื่อประหยัด Data อินเทอร์เน็ตของไรเดอร์

## 4. ยกระดับ System Hardening & Stress Test Bug Fixes
เราได้แก้ไขสถาปัตยกรรมระบบ 4 จุดหลักที่เป็นคอขวดเมื่อเจอกับ SignalR Stress Test:
*   **PostgreSQL Max Pool Size**: เพิ่ม `Max Pool Size=1024` ใน `appsettings.json` และ `docker-compose.yml` เพื่อป้องกัน DB Connection Pool Exhaustion ในจังหวะ burst โหลดสูง
*   **SignalR Connection Rider Caching**: เก็บพิกัด `RiderId` ใน `Context.Items` เมื่อ Rider เชื่อมต่อ SignalR และดึงมาใช้งานผ่าน `GetRiderIdAsync()` ทันทีเพื่อลดภาระการคิวรีฐานข้อมูลหา `RiderId` เหลือศูนย์ (0) ในช่วง GPS/Heartbeat Update
*   **Cache-Aside Pattern for Telemetry**:
    *   นำ Redis มาช่วยในการสตรีมพิกัดและสถานะ โดยเมื่อ Rider/Order เกิดการทรานซิชันสถานะใน `StateMachineService.cs` จะทำจัดเก็บข้อมูลใหม่ลง Redis cache ทันที (`riders:status:{riderId}` และ `riders:active_order:{riderId}`)
    *   ปรับปรุง `TelemetryService.cs` ให้ทำงานแบบ Cache-First เสมอ โดยจะดึงสถานะไรเดอร์และข้อมูลคำสั่งซื้อจาก Redis ก่อน และดึงจาก PostgreSQL เฉพาะเวลา Cache Miss เท่านั้น ซึ่งช่วยล้างคิวรีในฮอตพาร์ทออกไปได้มากกว่า 99%
*   **Redis Memory Leak Prevention**: ตั้งค่าหมดอายุ (TTL) **24 ชั่วโมง** ให้กับข้อมูล GPS ของ Rider (`riders:gps:{riderId}`) ใน `UpdateGpsAsync` ช่วยทำลายคีย์ทิ้งอัตโนมัติหากมี Rider หลุดออกไปแบบกะทันหัน
*   **RabbitMQ Consumer Prefetch Limit**: เพิ่ม `channel.BasicQos` ด้วยค่า `prefetchCount: 100` ใน `RabbitMqEventBus.Subscribe` เพื่อช่วยแบ่งการทำงานออกเป็นแบทช์ ป้องกันปัญหา Queue Flood
