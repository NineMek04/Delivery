## 🔒 1. การแบ่งแยกบทบาทสิทธิ์และสกัดเส้นทาง (Role-Based Routing Enforcement)

ระบบแบ่งผู้ใช้งานออกเป็น 3 บทบาทหลัก และบล็อกไม่ให้มีการใช้ลิ้งก์ข้ามสายเพื่อรักษาความปลอดภัยในระดับ Client-side logic:

### 🟢 1.1 บทบาทไรเดอร์ (Rider - Default Role)
- **สิทธิ์การใช้งาน:** เข้าถึงหน้าต่างหลัก `/`, หน้าต่างจัดส่งออเดอร์ `/delivery/active`, แผนที่นำทาง `/tracking`, และข้อมูลไรเดอร์ `/profile`
- **การบล็อก:** ห้ามเจาะเข้าสู่หน้าต่างประมวลผลสำหรับร้านค้าและลูกค้าเด็ดขาด

### 🟠 1.2 บทบาทพาร์ทเนอร์ร้านค้า (Store Partner)
- **สิทธิ์การใช้งาน:** ถูกจำกัดให้อยู่ภายใต้กลุ่มพาธ `/store/*` เช่น หน้าสำหรับจัดการออเดอร์ร้านอาหาร `/store/orders` และหน้าสรุปผลวิเคราะห์ร้านค้า `/store/summary`
- **การบล็อก:** หากพยายามเข้าใช้หน้าสำหรับไรเดอร์หรือลูกค้า ระบบจะยิงสั่งเตือน `authAlertProvider` ว่า *'สิทธิ์นี้ไม่ได้รับอนุญาตให้เข้า'* และบังคับตีกลับ (Redirect) มาหน้า `/store` ทันที

### 🔴 1.3 บทบาทลูกค้าผู้สั่งซื้อ (Customer)
- **สิทธิ์การใช้งาน:** เข้าใช้งานหน้าต่างกลุ่มพาธ `/customer/*` เช่น ร้านอาหารใกล้เคียง `/customer/shop/:shopId`, และประวัติการสั่งอาหารของผู้สั่ง `/customer/orders`
- **การบล็อก:** หากพยายามเข้าใช้หน้าของไรเดอร์หรือร้านค้า จะโดนตีกลับเข้าหาหน้า `/customer` ทันที

## ⚡ 2. กลไกการเด้งหน้าและรีเฟรชเส้นทางอัตโนมัติ (Dynamic Router Redirect & Refresh)

เพื่อความต่อเนื่องในงานออกแบบ UI เมื่อระดับสิทธิ์ใน Token ของคนขับหมดอายุ หรือไรเดอร์กดออกจากระบบ (Logout) เส้นทางการควบคุมจะต้องเด้งกลับไปที่หน้าล็อกอินโดยอัตโนมัติ (Reactive Screen Navigation):

- **ตัวเฝ้าดูความเปลี่ยนแปลง (Refresh Provider):**  
  ระบบทำสัญญาเฝ้าดูสายบริการตัวตนผ่าน `_routerRefreshProvider` ซึ่งจะคอยส่งสัญญาณ `ValueNotifier` ไปหาตัวควบคุมเส้นทางหลักของ GoRouter ทุกครั้งเมื่อสถานะล็อกอินเปลี่ยนแปลง:
  ```dart
  final _routerRefreshProvider = Provider<Listenable>((ref) {
    final notifier = ValueNotifier<int>(0);
    ref.listen(authServiceProvider, (_, __) {
      notifier.value++; // เพิ่มค่าเพื่อทริกเกอร์ให้ GoRouter ทำงาน Redirect อีกครั้ง
    });
    ref.onDispose(notifier.dispose);
    return notifier;
  });
  ```
- **การทริกเกอร์ตรวจสอบเส้นทาง:**  
  ค่าสัญญาณจะถูกป้อนไปที่ `refreshListenable` ของ `GoRouter` ซึ่งจะบังคับเรียกฟังก์ชัน `redirect` ขาเข้าเพื่อประเมินบทบาทความถูกต้องของ Token ปัจจุบันทันที หากผู้ใช้ยังไม่ได้เข้าสู่ระบบ จะเด้งตัวแอปกลับไปที่ `/login` เสมอแบบเรียลไทม์
