## 6. [ระบบงานสนับสนุนเพิ่มเติม] ระบบสำรองข้อมูลการจองไรเดอร์เมื่อ Redis ล่ม (PostgreSQL Fallback Lock)
* **DistributedLock Model:** สร้างตารางข้อมูลและดัชนี B-tree `"IX_DistributedLocks_ExpiresAt"` สำหรับรองรับการเก็บล็อกสำรองบน PostgreSQL เพื่อใช้เป็น Fail-safe
* **Schema Migration:** ทำการเพิ่มตารางผ่าน Entity Framework Core Migration (`AddDistributedLocks`) และสั่งรันอัปเดตโครงสร้างฐานข้อมูลผ่าน `dotnet ef database update`
* **RedisLockService Resilience:** ปรับปรุง [RedisLockService.cs](file:///c:/Users/ASUS/Desktop/Project/Delivery/BackendApi/Infrastructure/Redis/RedisLockService.cs) ให้ทำงานดักจับ Redis Connection exceptions แล้วสลับส่งคำสั่งไปจัดการล็อกในฐานข้อมูล PostgreSQL แทนการปฏิเสธการทำรายการ (Fail-safe Fallback)
* **Atomic PostgreSQL Query:** ใช้ SQL INSERT ... ON CONFLICT DO UPDATE ในการจองล็อกอย่างปลอดภัย ป้องกันปัญหา Race Condition 100% แม้สลับไปใช้ Database Fallback

  * **การแก้ไข:** แปลงรูปแบบไฟล์สคริปต์ดังกล่าวให้เป็น Linux Line Endings (LF เท่านั้น แบบไม่มี BOM) เรียบร้อย ทำให้ระบบสร้างและลงทะเบียนสิทธิ์ AppRole บน Vault ได้ถูกต้อง
* **ปัญหา Port 8080 ชนกันบนระบบปฏิบัติการ (Socket Bind Conflict):**
